# Переход на React + TypeScript

23–24 ноября 2026 г. сайт переписан с чистого JavaScript на React 19 + TypeScript со сборкой Vite. Оформление, адреса страниц и формат данных не изменились. Устройство новой версии описано в [Архитектуре](architecture.md).

## Как переписывали

- Разметка каждого компонента повторяет разметку, которую строил `app.js`: те же теги, классы и атрибуты. Стили (`styles.css`) перенесены без изменений.
- Логика вынесена из шаблонов в чистые функции `src/lib/` и покрыта тестами.
- Одно намеренное отличие: страница переводчицы В. Марковой (`#/translator/markova`). В старой версии она падала, потому что у двух произведений в содержании книги `x37` нет названия. Новая версия показывает страницу. См. [Известные проблемы](../maintenance/known-issues.md).
- Невидимые отличия:
  - приложение смонтировано в `<div id="root">`;
  - кнопка «← назад» вызывает `history.back()` из обработчика, а не через `javascript:` в ссылке;
  - книги каждого автора индексируются один раз, поэтому перечень авторов рисуется примерно за 40 мс вместо 650 мс.

Старая версия осталась в истории git: последний её коммит — `591821e`.

## Сверка со старой версией

Обе версии открываются на одном dev-сервере. Скрипты сверки сравнивают их в браузере, например через Chrome DevTools: `evaluate_script` с файлом скрипта.

1. Извлеките старую версию из git в `.legacy/` (папка в `.gitignore`):
   ```powershell
   npm run legacy
   ```
2. Запустите dev-сервер:
   ```powershell
   npm run dev
   ```
   Старая версия будет доступна на <http://localhost:5173/legacy/>, новая — на <http://localhost:5173/>.
3. На странице <http://localhost:5173/> выполните скрипт `tools/compare-legacy.js`. Для каждого маршрута он открывает обе версии в соседних iframe, ждёт отрисовки и сравнивает:
   - структуру DOM внутри `#app`: теги, классы, атрибуты, текст;
   - видимый текст с пробелами;
   - положение и размер каждого элемента шапки, меню и содержимого, с точностью до пикселя;
   - заголовок вкладки и активный пункт меню.

   Свой список маршрутов задаётся в `window.__compareRoutes`, ширина — в `window.__compareWidth`. Цветная палитра включается через `localStorage.palette = 'color'`.
4. `tools/interactions.js` — одинаковый сценарий для обеих версий:
   - теги поиска, ссылки сортировки и вида;
   - сортировка таблицы произведений и фильтр по виду;
   - переход по букве;
   - прокрутка наверх при переходе;
   - палитра;
   - «← назад»;
   - ссылка года издания.

   Скрипт запускают в каждой версии отдельно и сравнивают результаты. Вкладка должна быть на переднем плане: в фоновой вкладке плавная прокрутка не идёт.

## Результаты

- 47 маршрутов, включая все разделы, виды, сортировки, фильтры, страницы людей, книг и серий, при ширине 1280 и 375 px: совпадают все, кроме страницы Марковой.
- Цветная палитра: совпадают все 8 проверенных маршрутов.
- Сценарий взаимодействий: все 15 шагов дают одинаковый результат.
- Деревья доступности обеих версий одинаковы.
- После переноса проекта в корень репозитория повторная сверка 26 маршрутов прошла без отличий.

## На что обращать внимание при правке компонентов

- React делит текст на несколько текстовых узлов там, где в JSX стоят вставки (`{t} · {n}`). Из-за этого ширина строки может отличаться на доли пикселя от одного текстового узла. Если важно точное совпадение, собирайте текст одной шаблонной строкой: ``{`${t} · ${n}`}``.
- Не оборачивайте содержимое страницы в лишние `div`. Правила вроде `.section-title:first-child` и `h1 + .sub` зависят от того, что элементы — прямые соседи внутри `#app`.
- Ключи списков должны быть уникальны. Группы изданий по издательству могут повторяться (`groupRuns`), поэтому для них ключ — индекс.
